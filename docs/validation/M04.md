# M04 validation — one finite-lived organism with local perception

Date: 2026-11-08. Status: **implemented; automated tests passed; roadmap manual test passed in Chromium (Playwright) on an isolated stack; live database migration rehearsed on a copy but not yet applied (your live run was running) — a human visual pass is still recommended**.

## Delivered scope

- **Organism state** (state schema 4). Each organism has:
  - an opaque ID (`org-0001`), birth tick, generation 0 and no parents;
  - a position and integer energy (capacity 100, start 60);
  - an engine-private sampled lifespan;
  - alive/dead status with death tick, cause (`age` | `starvation` | `exhaustion`) and retired energy.

  Organisms and the lifecycle rules are part of the state hash, snapshots and replay. Schema-2 and schema-3 runs keep byte-identical hashes.
- **Seeding.** Lifespans are drawn from the run's seeded PRNG after the cell draws: uniform 160–240 by default, narrowed only by labeled fixtures. They are recorded in the manifest and initial state, so replay never re-draws them. The seed endowment counts as initial energy.
- **Tick order** (`engine/world.py`):
  1. environmental inflow;
  2. age deaths;
  3. upkeep (1 energy, actual amount dissipated);
  4. starvation deaths;
  5. each living organism, in stable ID order, receives an observation, its policy proposes, and the engine validates and applies the proposal;
  6. exhaustion death if a valid action spent the last energy;
  7. extinction check.
- **Perception** (`engine/perception.py`). A frozen DTO containing only:
  - Manhattan radius-2 cells as relative offsets, clipped at the edges (6 cells at a corner, 13 in the interior);
  - other organisms within the radius;
  - the organism's own age and energy;
  - general rules and a finite-life note.

  It never contains the tick, seed, PRNG state, ledger, lifespan or deadline, absolute position, world size, or anything outside the radius.
- **Actions** (`domain/actions.py`, `engine/actions.py`):
  - `wait` is free.
  - `move(north|east|south|west)` costs `1 + floor(packed / 2)` energy.
  - Out-of-bounds, occupied, unaffordable, unknown or malformed proposals produce a `diagnostic` event with no state changes. Upkeep is independent and never a rejection penalty.
- **Death.** The organism's remaining energy is retired through the ledger. No cell changes. The record is terminal.
- **Extinction.** When the last death happens, exactly one `extinction` event is written and the run is archived:
  - every further tick is refused with a 409, and the runner auto-pauses and snapshots;
  - this holds across restarts;
  - nothing is ever reseeded.

  Organism-free runs are never extinct.
- **Ledger.** Cells plus living organisms equals initial energy, plus inflow, minus dissipation (upkeep and movement), minus death retirement. Every event's ledger entries keep the finer category.
- **Test policies** (`cognition/fixture_policy.py`). Scripted proposals indexed by age. They receive only `Observation` objects and refuse anything else.
- **Fixtures** (dev mode only, labeled TEST FIXTURE and "scripted, not autonomous"): `corner_perception`, `starvation`, `age_limit`, plus the existing `zero_inflow`. Standard runs have no organisms until cognition arrives (M06/M07).
- **Persistence.** Database layout version 4, reached by an additive 3→4 migration recorded in `schema_migrations`:
  - `event_organism_changes` stores exact JSON before/after deltas;
  - `events.actor_id` and `events.payload_json` hold the observation supplied, the proposal and the observer-only origin;
  - an `organisms` projection is verified against replay on load;
  - manifest version 3 seals the lifecycle rules and initial organisms;
  - snapshot format 2 adds organisms. Format 1 snapshots are still read.
- **API.**
  - The frame contract is version 4 and adds `organisms`, `extinct` and `changed_organisms`. The ledger shows energy in cells and in organisms.
  - New endpoint: `GET /api/organisms/{id}` (`at_tick`).
  - Observer views withhold the lifespan while the organism is alive.
- **UI.**
  - Organism markers on the grid, with a ring around the selected one. The dead leave no mark.
  - An *Organisms* panel: list, status, energy, age, position; death details and the lifespan only after death; the latest decision, with the exact supplied observation as a table, the proposal and the outcome; recent events.
  - A toggleable local-view overlay drawn from the recorded observation.
  - An EXTINCT banner, with live controls disabled while history stays available.
  - New event descriptions and ledger lines.

Not added: extraction or modification (M05), cognition or scheduling cadence (M06), LLMs, reproduction, social interaction, or immortality toggles. `AGENTS.md` is unchanged (SHA-256 `827d5eec…`).

## Live data

The migration was rehearsed on a copy of `data/genesis.sqlite3` (layout 3, 6 runs, including your schema-3 run `8fddc2c9` at 4,315 ticks at the time of copying):
- every history row was unchanged;
- migrations recorded as (2→3) and (3→4);
- every run kept its exact hash and fully replays.

**Applied after an incident.** At first the live backend was left running M03, so as not to stop run `8fddc2c9`. Vite's dev server, however, hot-reloaded the browser to the M04 page. That page correctly refused the M03 backend's version-3 frames, but displayed the refusal as "Backend unavailable", which looked like an outage.

The fix:
1. Took a backup with the SQLite backup API (`genesis-pre-m04-backup.sqlite3` in the session scratchpad).
2. Stopped the backend gracefully and started it on M04. Migration 3→4 was applied, and the run was restored from its tick-8,700 snapshot with nothing to replay, paused, ledger balanced.
3. Verified in a real browser: Connected, tick 8,700.

The run needs **Resume** to continue. As a lasting fix, the page now distinguishes a version mismatch from an outage: it says "Version mismatch" and asks for a backend restart. A test covers frame versions 1 and 3.

Lesson: in development, the backend and frontend must be restarted together, because the dev server updates the page immediately while the backend keeps running old code.

## Fixed during M04 development

1. The reducer applied organism deltas one field at a time, so a death passed through an invalid "dead without a death record" state and was rejected by the invariants. Changes are now applied to a working record and validated once per organism per event.
2. Two cosmetic UI defects: an oversized checkbox, and a footer that said "No organisms yet" while one was alive.

## Known limits / unverified

- **Human visual check** is still pending. The organism marker is a plain square, and the overlay colour is the only cue for the local view; the table carries the exact values.
- **Decision cadence:** organisms decide every tick in M04. The proposed 4-tick cadence with triggers belongs to M06.
- **Scripted fixtures only.** Behaviour shows mechanics, not autonomy. Organisms cannot gain energy until extraction (M05), so every M04 organism dies within its start energy or lifespan.
- **No contested cells yet.** With one organism per fixture, the "occupied" rejection is tested in unit tests but not shown in the browser. Ordering of multi-organism conflicts is M09.
- **Extinction stops everything,** including environmental inflow, as proposed in the architecture. Organism-free runs keep advancing.
