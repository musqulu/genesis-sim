# Genesis technical research

Research date: 2026-11-07; runtime/API update: 2026-11-08. Status: source review and recommendations, not an implementation or benchmark. Read alongside [ARCHITECTURE.md](ARCHITECTURE.md), [DECISIONS.md](DECISIONS.md), and the [constitution](../AGENTS.md).

## Scope and evidence

The local project contained the constitution and no application files at inspection. The directory was not a Git working tree. This review read upstream files over HTTP without cloning, vendoring, installing, executing, or modifying external code. No models were downloaded or benchmarked.

Generative Agents was inspected at commit **`fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4`**, dated 2023-08-11, resolved from the repository's `main` API endpoint. Links below pin that revision. This is a static review of the named paths, not an audit of every asset or stored simulation. Runtime compatibility, model behavior, and performance remain unverified. The research paper is useful context, but the recommendations below follow actual implementation paths.

**Recommendation:** adapt selected cognition patterns, use maintained libraries directly, and implement Genesis's small physics and persistence core independently. A fork of the whole application would require removing most of its assumptions while retaining substantial coupling.

“Adapt” below means preserve a useful design while changing its contracts. It does not mean source has already been copied. “Reimplement” means a new Genesis implementation. No upstream module is recommended for unchanged production reuse.

## Inference and maintainability implications

The inspected call graph does not support a universal “one call per agent per tick” estimate. Routine path steps may need no new plan; observing a new event may invoke both importance generation and an embedding request. Daily planning, conversation and reflection add bursts. Retries multiply calls. These are static observations, not measured cost figures. Genesis should meter requests, prompt/output tokens, queue time, load time and generation time by organism and purpose.

The two [dependency manifests](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/requirements.txt) and [frontend manifest](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/environment/frontend_server/requirements.txt) include Django 2.2, OpenAI 0.27.0, gensim 3.8.0, Selenium, scientific plotting and storage packages. Their NumPy/pandas and other versions differ. They are not a minimal reusable agent library. Wildcard imports, `sys.path` changes, generated `utils.py`, relative filesystem paths and mutable cross-persona access increase extraction cost. Do not install these manifests or assume they work with a current Apple Silicon environment.

No general resource ledger, mortality/reproduction subsystem or full world-event reducer was identified in the reviewed execution path. Those are core Genesis mechanisms, not small configuration changes. This conclusion concerns the reviewed repository, not all later implementations inspired by the paper.

For any future source adaptation, retain relevant notices and the license, identify modified files, and preserve applicable NOTICE material if supplied. Record original path, pinned commit, local destination and modifications in a third-party inventory. A conceptual independent implementation should still cite the research influence. Individual assets and dependencies require their own provenance checks; the root license is not proof of rights to every third-party asset. No town artwork is needed.

Before copying even a small helper, compare extraction cost against an independent implementation and add contract tests. Retrieval is the strongest candidate for a small attributed adaptation, but its edge cases and persona dependencies need removal. Unchanged reuse of the whole package is not justified. Prefer direct library reuse for validation, HTTP, persistence and testing; avoid writing substitutes for those mature mechanisms.

## MLX and API update — 2026-11-08

The user's recalled name “molx” is interpreted as **MLX**. MLX-LM is the selected local LLM layer; Ollama is excluded from the implementation plan. API access is also an initial capability, distinct from later experimental comparison tooling. The reference experiment still starts with a shared local model, as the constitution specifies.

Read-only inspection of MLX-LM [`server.py` at `56230fa02b8ff8330daf26dc95c28480423ed5fe`](https://github.com/ml-explore/mlx-lm/blob/56230fa02b8ff8330daf26dc95c28480423ed5fe/mlx_lm/server.py) found `/v1/chat/completions`, model-list and health routes, but no `response_format`/`json_schema` handling. The server also carries a warning against production use due to basic security checks. This supports protocol experimentation, not a claim of full endpoint/schema compatibility or a recommendation to expose the bundled server publicly. Prefer MLX-LM's Python API in a local worker, and an independent outbound HTTP adapter for chosen external endpoints. Verify schema adherence and endpoint behavior at implementation time.

Provider portability requires more than changing a URL: normalize responses, errors and usage, handle absent model fingerprints, and keep credentials outside history. Preserve the same bounded organism inputs and strict engine validation for every provider. Hosted aliases may change behind the same name; replay uses recorded replies/effects and must work without network access. These are Genesis design recommendations, not claims that every API supports the same features.

## Research conclusions that change the roadmap

1. Introduce append-only causal history with the first changing environment, and basic replay before LLM integration.
2. Introduce finite lives and energy with the first organisms; immortal free-action prototypes would test a different system.
3. Build action validation and a recorded-response provider before local MLX-LM and API adapters. Deliver each adapter as a separate testable gate (M07A/M07B); comparative experiments remain later work.
4. Add memory retrieval before expensive reflection. Measure whether evidence reaches decisions rather than requiring a preferred strategy.
5. Split reproduction mechanics from richer inheritance, while giving even the first offspring a fresh identity and minimal imperfect traits.
6. Call the final MVP gate “generational experiment,” not “evolution.” Record evidence of what happened without asserting adaptation or consciousness.
