# M03 validation — snapshots, restart and basic replay

Date: 2026-11-08. Status: **implemented; automated tests passed; full browser acceptance passed in Chromium (Playwright) on an isolated stack; live database migrated and verified — a human visual pass is still recommended**.

## Delivered scope

- **Versioned, sealed manifests** (`persistence/manifest.py`). Each run's manifest is canonical JSON sealed with SHA-256. It is checked against the stored columns on every load; a tampered or unsupported manifest stops loading. New runs use manifest version 2 and state schema 3, which records the post-seeding PRNG state and includes it in the state hash. M02 runs are sealed as manifest version 1, state schema 2, and keep their original hashes byte-for-byte.
- **Events module** (`persistence/events.py`). Writes are append-only. Only the next sequence is accepted, so a duplicate or skipped sequence raises `SequenceError` and the whole tick rolls back. `read_events` reconstructs typed events with their exact deltas and ledger entries.
- **Snapshots** (`persistence/snapshots.py`), format 1:
  - Payload: config, cells, ledger, PRNG state, scheduler information (next tick, next inflow tick, rule order) and the event boundary.
  - Integrity: a checksum over the canonical payload.
  - When written: at creation (tick 0), every 100 ticks inside the tick transaction, and on pause, auto-pause, new-run switch and graceful close. Only committed ticks are snapshotted, and existing snapshots are never overwritten.
  - Validation checks the checksum, format, decode, config, the recorded tick hash and the event boundary.
- **Replay** (`persistence/replay.py`):
  - Starts from the manifest's stored initial state or the newest valid snapshot, then applies the recorded deltas only. No rule, seeding or model is invoked.
  - Checks sequence continuity, delta chaining (each `before` must equal the current value), the recorded tick hashes and the ledger balance.
  - A missing or inconsistent record raises `HistoryError`. A tick outside 0–live raises `HistoryUnavailable`.
- **Restart.** `load_run` rebuilds the state from snapshot plus tail, verifying every tail tick, then requires the `cells` projection and the last event sequence to agree. Skipped snapshots are written to `technical_log`. The restart always comes back paused, and the startup source is shown in the UI and in `/api/health`.
- **Migration.** On first start, a database at layout v2 (M02) becomes v3:
  - It gains the new tables and manifest columns, and existing manifests are sealed.
  - No events, ticks, cells or control records are rewritten.
  - The migration is recorded in `schema_migrations`.
  - Unknown or newer layouts are refused before any table is created.
- **API.**
  - New: `GET /api/history/{tick}?source=snapshot|initial` (read-only) and `GET /api/snapshots`.
  - New filters: `max_tick` on events and `at_tick` on cell inspection.
  - The frame contract moved to `schema_version` 3 and gained `state_schema`, `manifest_hash` and `restored_from`.
- **UI.**
  - A *Recorded history* panel: tick slider and input, a choice between nearest snapshot and full replay, the rebuild source, the hash check, skipped snapshots and the snapshot list.
  - A *HISTORY* banner and tag, clearly separate from live mode. In history mode the run controls and **New run** are disabled; the grid, inspector, ledger and events show the chosen tick only; and the live tick keeps advancing in the banner.

Not added: advanced timelines, branching, compression policy, backup/disaster-recovery tooling, organisms, or later milestones. `AGENTS.md` is unchanged (SHA-256 `827d5eec…`).

## Known limits / unverified

- **Human visual check** of the history styling is still pending.
- **Legacy (schema 2) runs** have no snapshots until their next 100th tick, pause or close, so their first M03 startup does a full replay. That takes 0.48 s for the 1,333-tick run here.
- **History seeks** verify only the target tick's hash; startup verifies every tick in the tail. Any intermediate inconsistency still fails, because deltas must chain.
- **Determinism change:** seed-42 hashes for **new** runs differ from M02's documented `4bd34870…`, because schema 3 includes the PRNG state. Same-schema runs stay identical: tick 100 is `57670625…` and tick 150 is `d36985b4…`.
- **Not yet built:** snapshot pruning or compression, `backup` tooling, disk-full injection and corrupted-event repair (M15). Corrupt events stop loading by design.
- **History UI scope:** no scrubbing animation, timeline or cross-run browsing (M14).
