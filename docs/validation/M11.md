# M11 validation — bounded reflection with evidence

Date: 2026-11-11. Status: **implemented; automated tests passed; fixture check passed in Chromium (Playwright); observed live on 2026-11-11 (below), where a truncation problem was found and fixed.**

## Scope

| | |
|---|---|
| State | **State schema 10**, rules `m11-rules-1`.<br>• Organisms gain `reflected_at_tick`.<br>• Memory records gain the kind `reflection` with an `evidence` tuple, the ids of cited records. Evidence is serialised only for reflections, so earlier records hash identically.<br>• No DB layout change; snapshots carry the new fields. |
| Trigger | A due decision opportunity becomes a **reflection opportunity** (never both in one tick) when all of these hold:<br>• memory and reflection are enabled;<br>• at least 20 ticks have passed since the last opportunity (`reflection_cooldown`);<br>• at least 8 active salient records (salience ≥ 2: own outcomes, read messages; not reflections) were acquired since then (`reflection_threshold`);<br>• the organism can pay the cognition fee and the reflection fee and keep 1 energy.<br>The opportunity is recorded when scheduled, so an empty, rejected or unparsed reply still starts the cooldown. Calls are bounded: a reflection uses the organism's decision slot, adding no requests. |
| Request (`reflection-v1`) | Purpose `reflect`, schema `genesis.reflection.v1`, the same request id, barrier, persistence and providers.<br>• **Context:** its status (age, energy, carried material, life note), its newest non-reflection records (offsets only, at most `reflection_context_max` = 16), its tendencies, the reply schema.<br>• **Prompt:** "This time you do not act: you may reflect…"; up to 2 short interpretations, each citing ids; *"Writing none is fine."* No action schema. |
| Validation | **Parser:** shape only. `{"reflections": [...]}`, at most 2 items, each with text and 1–8 evidence ids. One code fence is tolerated, as for actions.<br>**Engine:** the whole reply is rejected with **no state effect** when:<br>• evidence is empty, or cites any id not shown in that request: unknown, another organism's, or older than the context window (`invalid_evidence`);<br>• a text exceeds 256 bytes (`invalid_arguments`);<br>• the fee is unaffordable.<br>Reflections cannot cite reflections, so there are no recursive chains. |
| Storage and cost | **Accepted:** fee 2 (`reflection_fee`, dissipated). Each reflection is then stored by the normal memory write (paid per started KiB, oldest-first eviction) with salience 2, keywords `reflection` plus the tags of its sources, and its evidence links.<br>**Empty reply:** accepted, free, stores nothing.<br>**Sources are never altered** (tested). If a cited record is later forgotten, the link stays in history (observer only). |
| Observer | • **Memory inspector:** each record's nature is shown: **fact** (observation, outcome), **claim** (message), **interpretation** (reflection, with *cites m00012, …*).<br>• **Decision inspector:** shows *reflection request: N of its own records* instead of an observation, and the exact `reflection-v1` prompt.<br>• **Organism panel:** *Reflected: 1 interpretation(s) (−2 energy)*.<br>• **Behaviour stats** count `reflect`. |
| Fixtures (dev, scripted) | `reflection_probe`: a square walker (start energy 100) reflects at ticks 9 and 29, each time citing its two newest records.<br>`reflection_invalid`: identical, but cites a record it never had. Both rejected, nothing stored; the opportunities and cooldown are still used. Earlier fixtures keep reflection off. |

Not added: weight updates, mandatory insight, recursive reflection, tendency changes, and reflection on received messages as a separate trigger.

## Choices made within the proposals (reversible)

1. **"Salient"** means salience ≥ 2: the organism's own accepted actions and read messages. Observations (salience 1) and reflections do not count.
2. **Reflection salience is 2** (equal to outcomes and messages). Making it higher would have changed recall normalisation for earlier runs.
3. **A reflection opportunity shows the newest 16 non-reflection records.** It does not use the recall ranking, so the evidence set is simple to check.
4. **A whole reply is rejected if any part is invalid.** Partial acceptance would make provenance harder to audit.
5. **No action is taken in a reflection tick.** Upkeep and the decision fee still apply, as for waiting.

**Examples** (verbatim; interpretations can be wrong, e.g. one calls `dy=1` "north"):
- *"Org-0010 is a consistent neighbor who offers trade; my high caution keeps me from engaging yet."* (org-0001)
- *"Sustained dialogue with org-0001 across 14 ticks demonstrates high transmission drive, yet I still hold 3 material and 18 energy, indicating a gap between signaling and actual resource exchange."* (org-0010, written at tick 18 after the fix)

**Fix.** Reflection requests now get their own output cap, `reflection_max_output_tokens` = 512, in the MLX settings and API profiles. Decisions keep 256. The cap is sealed with each run's provider profile; profiles sealed earlier default to 512. It is a provider setting, so world state and hashes are unaffected, and the `c4e41be5` history stays valid.
