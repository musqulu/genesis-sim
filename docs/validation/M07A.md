## Delivered scope

- **Worker** (`providers/mlx_worker.py`). A self-contained subprocess run under `GENESIS_MLX_PYTHON`. It speaks a JSON-lines protocol and imports nothing from Genesis. It holds one resident model and handles one request at a time, checks the 4096-token context and 256-token output limits before generating, seeds sampling per request, keeps thinking disabled, and reports the finish reason.
  - A name clash (Genesis's `providers/mlx.py` shadowing Apple's `mlx` package) was found in the first live start and fixed by dropping the script's own directory from `sys.path`.
- **Provider** (`providers/mlx.py`). The worker starts lazily on the first decision. Failures are typed:

  | Failure | Handling |
  |---|---|
  | Timeout | The worker is killed, so its late output can never be used, and the request is retried once. |
  | `worker_crashed` | Technical pause. Resume restarts the worker. |
  | Config or context overflow | No retry. |

  Every request is matched by a per-request nonce. Health metrics are kept. The provider also handles model discovery (no loading) and builds the profile sealed in the run manifest.
- **Prompt** (`cognition/prompts.py`, `decision-v1`). It states the rules and the organism's situation only, with no role, goal or strategy. The user message is exactly the request context. The action schema is in the prompt and output is validated by the existing strict parser. Constrained decoding is not claimed.
- **Runs.**
  - `POST /api/runs {cognition: "mlx:<id>"}` creates a one-organism live run (labeled `LIVE MODEL`, seeded placement) with default M06 cadence and fee.
  - `GET /api/models` lists local models and runtime status.
  - The frame shows provider identity, profile and worker health.
  - Each decision stores the exact prompt, sampling, limits, runtime and finish reason.
  - The provider is fixed per run; an unavailable model never falls back to anything.
- **UI.**
  - A *Cognition* selector at new-run setup.
  - A live-model label: "local MLX-LM · … — live model, nondeterministic".
  - A worker health line.
  - The decision inspector's *Exact prompt sent* section with settings.
  - Live organisms are labeled as such, not as scripted.

Not added: API transport (M07B), multiple organisms (M09), broad benchmarking, reflection, Ollama, constrained decoding.

## Roadmap manual test with the real model (Chromium, 19/19 checks)

1. **Model offered.** *Cognition* listed `Qwen3.8-27B-Uncensored-MLX/8-bit (29.5 GB)`, plus two other local MLX folders. Nothing was downloaded.
2. **One-organism run.** One organism labeled `LIVE MODEL`; provider `mlx`; not a fixture. The manifest profile was sealed (64-character digest, mlx-lm 0.31.3, `decision-v1`, 4096 context). The worker was *stopped* until the first decision.
3. **Three decision attempts.** Logical time waited at the barrier while the model worked and the page stayed live. Attempts were made at ticks 1, 2 and 6; tick 2 came early from the local-change trigger after the move.
   - Tick 1: valid, accepted — moved west, "toward loose material at (-2,0)". 979/37 tokens, 3.5 s.
   - Tick 2: valid, **rejected `insufficient_source`** — tried to extract 5 material from its own cell. 990/37 tokens, 3.3 s.
   - Tick 6: valid, **rejected `insufficient_source`** — same mistake. 992/64 tokens, 4.8 s.
   - Every attempt has its raw output, exact prompt, model and runtime recorded and links to its event. The inspector showed all of this, and worker health read ready, pid, 28.6 GB.
4. **Worker killed during a request.** `kill -9` during the tick-10 request gave a technical pause, `worker_crashed`, with tick 9 committed and tick 10 pending. Nothing was consumed, and the tick stayed fixed.
5. **Restore and resume.** Resume restarted the worker (one restart) and committed tick 10 exactly once: accepted, moved west, now correctly toward the material.
6. **Replay with inference disabled.** After shutdown no worker was left. The backend restarted with a nonexistent interpreter and no model folder, and returned the same tick and hash, paused. A full replay from the initial state to the live tick verified with zero inference. Recorded raw outputs and prompts remained inspectable, and no models were offered.

There were no console errors. The same seed produced the same three outputs in two separate runs, because sampling is seeded from the input hash. This is an observation on this machine and runtime, not a determinism guarantee.

Regressions on the final build, each on a fresh database without MLX configured: M01/M02 **33/33**, M03 **24/24**, M04 **30/30**, M05 **28/28**, M06 **26/26**.

## Fixed during M07A

1. **Module shadowing:** Genesis's `providers/mlx.py` shadowed Apple's `mlx` package inside the worker. Fixed by isolating the worker's `sys.path`.
2. **Narrow-layout regression:** long model names in the new *Cognition* `<select>` widened the page at 420 px and broke the M01 resize check. Selects are now capped to their container; `full.js` passes again.
3. **Test-script assumptions:** my scripts assumed fixed decision ticks (1/5/9). Live decisions also follow the local-change trigger, so the script now adapts.

## Observations (not defects, not tuned)

- **Relative-offset confusion.** After moving, the model twice proposed extracting material from its new cell, apparently mistaking which observed cell held material. The engine rejected both (`insufficient_source`) and nothing was corrected. Whether the prompt's description of relative offsets is clear enough is an open prompt question for a later, labeled experiment, not a reason to script behaviour.
- **Schema adherence** was 4/4 valid JSON in the live trial, and 3/3 and 2/2 in the earlier smoke tests. That is too small a sample to make a reliability claim (O13 stays open).

## Known limits / unverified

- **Human visual check** of the live-model UI is still pending.
- **Cold load** time from disk was not measured. The 900 s load timeout is generous, and the 120 s request timeout was not hit by the real model.
- **Digest:** the file-manifest digest identifies installed files but is not a cryptographic hash of the weights.
- **Startup:** the documented startup command needs `GENESIS_MLX_PYTHON` for live-model runs. Without it, live runs are not offered and existing ones replay normally; resuming them would pause with a config error.
- **Live data:** your live database was backed up (`genesis-pre-m07a-backup.sqlite3` in the session scratchpad). The live backend was restarted with `GENESIS_MLX_PYTHON` and `GENESIS_MLX_MODEL_DIRS`, so the model is selectable in the app. Your run `5878da6b` was **running at tick 54,015** and was restored paused at 54,019 with the ledger balanced. It is environment-only and needs **Resume**. The audit reported 0 problems. No live-model run exists in your data yet.
- **Folders that aren't complete models:** discovery also lists `Qwen3.8-27B-MTP-8bit` (0.5 GB). That folder looks like a multi-token-prediction add-on rather than a complete model, and selecting it was not tested.
