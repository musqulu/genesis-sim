# M07B validation — configurable API-connected models

Date: 2026-11-09. Status: **implemented; automated tests passed; roadmap manual test passed in Chromium (Playwright) against a real self-hosted endpoint (vllm-mlx serving your Qwen model). The Replicate live check is still unverified: it needs your token and a chosen model.**

## Scope

| | |
|---|---|
| Adapters | `openai_chat` (OpenAI-compatible `/chat/completions`) and **`replicate`**. Replicate is a dedicated adapter for its predictions API, which is not chat-completions compatible; it was added at your request and is noted in ROADMAP and DECISIONS. |
| Configuration | `config/providers.toml`, override with `GENESIS_PROVIDERS_FILE`. The file holds **no secrets**; `api_key_env` names the variable that holds the key. Plain `http` is accepted only for loopback; remote endpoints must use `https`. Unknown settings, such as an inline `api_key`, are refused. |
| Selection | `cognition: "api:<profile id>"`, appearing in the Model list as *API · label · model*. Profiles that are missing a model or a key are shown disabled, with the reason. A **Check connection** probe creates nothing. |
| Sealing | When a run is created, its profile is sealed into the manifest without credentials. The provider is rebuilt from that sealed record, so editing the file later never changes an existing run. For Replicate, the model's **version is pinned** and its declared inputs are read once at creation. |
| Prompt and validation | Same `decision-v1` messages and the same strict parser and engine as M07A. Only inputs the endpoint supports are sent. For Replicate the system text goes to `system_prompt` when the model has one; otherwise it is placed before the prompt, and that choice is recorded. |
| `extra_body` | Endpoint-specific request fields, sent as given and recorded with each decision. They cannot override the model, prompt, limits, sampling or format. Used here to turn off Qwen's thinking mode (`chat_template_kwargs.enable_thinking = false`), matching M07A's local worker. |
| Errors | Typed and redacted, using the existing barrier: one bounded retry, then a technical pause with no ecological time passing.<br>• Retried once: transport, timeout, `rate_limited` (honours `Retry-After`, capped at 30 s), unavailable (5xx).<br>• Not retried: `auth` (401/403), `config`, `protocol`, `budget`, `remote_failed`.<br>• An unfinished Replicate prediction is cancelled on timeout. |
| Budget | Per-run `max_requests` and `max_total_tokens`. Totals are restored from recorded decisions when the run loads. Reaching the budget pauses the run; it never touches the world. |
| Usage | Unknown stays unknown. vllm-mlx reports `prompt_tokens: 0`, which is impossible for a real prompt, so it is recorded as unknown. |
| UI | The stage tag shows **SELF-HOSTED API** or **REMOTE API** plus endpoint and model. The health line shows *API connection: status · endpoint · latency · requests/failures · budget*. No frame version change (still v7). |
| Dependency | `httpx2`, which was already locked as a dev dependency, moved to the runtime dependencies. `uv lock --offline` was used; nothing was downloaded. |

Not added: mixed-model populations, mid-run switching, automatic fallback, streaming, other vendor protocols, and any prompt, physics or M08+ work.

## Roadmap manual test (Chromium, `m07b.js`, all checks passed)

Endpoint: `vllm-mlx serve ~/models/Qwen3.8-27B-Uncensored-MLX/8-bit --port 8090` with `HF_HUB_OFFLINE=1` (local files only). The Genesis backend ran with **no MLX runtime** (`GENESIS_MLX_PYTHON=/nonexistent`).

1. **Configure and select.** The Model list showed *API · vllm-mlx on this Mac · Qwen3.8-27B-Uncensored-MLX/8-bit*, with the Replicate profile disabled because no model is set. Check connection reported "Connected; … is served".
2. **One-organism run.** The provider was `api`/`local-vllm`, the stage read *SELF-HOSTED API · 127.0.0.1:8090 · … — live model, nondeterministic*, and the sealed profile contained no credential.
3. **Six attempts** (ticks 1, 2, 3, 4, 8, 9). All six replies were valid JSON and all were accepted: extract energy 10, move west, move west, extract material 5, extract energy 10, extract energy 10. Each used 26–55 output tokens and took 2.7–4.3 s. The exact prompt, endpoint, sampling and event link were recorded for every attempt. **Genesis started no MLX worker.**
4. **Interrupted endpoint.** The server was killed while a request was in flight. The run paused with a `transport` problem at pending tick 14, tick 13 stayed committed, nothing was consumed, and the provider was not switched.
5. **Resume.** After the server restarted, tick 14 committed exactly once.
6. **Replay offline.** With the server stopped and the backend restarted with no profiles file, the run returned at the same tick and hash. A full replay from the initial state verified, and the recorded prompts and outputs remained inspectable.

No console errors. Regressions on the final build: **full, M03, M04, M05, M06, M07 (real MLX model) and the UI-01 fullscreen/narrow checks all passed**. The M07 script's worker check now ignores workers belonging to your own backend on :8000.

**One live observation:** with thinking left on (the server default), Qwen produced reasoning prose cut off at 256 tokens with no JSON. With thinking off, as in M07A, it answered in valid JSON (seen in a single direct request before the run). The raw output is never repaired; this is only the request setting.

## Unverified / known limits

- **Replicate live call:** not verified. To check it:
  1. set `model = "owner/name"` in `config/providers.toml`;
  2. `export REPLICATE_API_TOKEN=…` in the shell that starts the backend;
  3. restart the backend and run a few decisions.

  Replicate's own docs list the statuses as `starting/processing/succeeded/failed/canceled`. The adapter was built from those docs and tested only against the local fixture. Official models without a version id use the model-level endpoint, and their revision is recorded as unknown.
- **Prompt tokens from vllm-mlx** are unknown, because the server reports 0. Budgets therefore count output tokens only for this endpoint.
- **Seed** is sent, but the same seed is not guaranteed to give the same output.
- **Human visual pass** of the new selector, check button and labels is still recommended.
