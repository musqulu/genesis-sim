# M02 validation — deterministic environment and resource accounting

Date: 2026-11-08. Status: **implemented; automated tests passed; full browser acceptance (M01 regression + M02) passed in Chromium via Playwright on an isolated stack — a human visual pass is still recommended**.

## Delivered scope

- Cells carry integer `energy` (0–100), `loose_material` and `packed_material` (0–8, **inactive**: no rule changes it).
- Seeded initialization (`random.Random(seed)`, recorded as `python-random-mt19937`): per cell, energy uniform 0–100, then a 25% chance of 1–10 loose material. These distributions are provisional (O01); nothing is tuned for viability.
- One rule, `env.energy_inflow.v1`: when the new tick is a multiple of 10, each cell gains up to 1 energy, capped at 100. Only the **actual** gain is credited; full cells get zero. Events record requested, credited and blocked totals and every changed cell's exact before/after. `inflow_amount = 0` disables the rule (the `zero_inflow` fixture).
- A `Ledger` (initial, inflow, dissipation, death retirement, retired material) is reconciled against actual cell contents before every commit; a mismatch is a technical failure that pauses the run.
- Each tick commits in one `BEGIN IMMEDIATE` transaction: events, per-cell deltas, ledger entries, cell state, tick hash (and the step's control record). Failure rolls back everything.
- `run_created` (`init.seeded.v1`) is event 1; every later state change has a causal event with a rule ID. Operator controls (start/resume/pause/step/speed/auto-pause) go to `control_log` (wall-clock metadata, excluded from hashes).
- Controls: Start, Pause, Resume, Step, Speed (1–50 ticks/s in the UI; API 1–1000), plus an optional "Pause at tick" so runs can stop exactly at a target. Step is refused while running; command IDs make repeated commands idempotent. A restarted backend always comes back paused at the last committed tick.
- UI: color legend, run controls, event list with detail (rule ID, cause, requested/credited/blocked, exact per-cell deltas, ledger entry), cell inspector with recent changes linking to events, ledger panel. The canvas shows energy as brightness, loose material as an amber square, and outlines cells changed this tick (or by the selected event).
- Fixtures (`zero_inflow`) exist only when the backend starts with `GENESIS_DEV=1`; they create a new run labeled "TEST FIXTURE".

Not added: organisms, decay, diffusion, weather, complex cell schemas, viability rules, snapshots/replay (M03), models. `AGENTS.md` retains SHA-256 `827d5eec…834aa` (unchanged).

## SQLite runtime and WAL

Runtime: SQLite 3.53.1 (uv Python 3.12). WAL is enabled only if the version is ≥ 3.51.3 or a fixed backport (3.50.7, 3.44.6) **and** `PRAGMA journal_mode=WAL` actually returns `wal` for the file; otherwise rollback journaling is kept and the reason is exposed at `/api/health`. Here: `WAL verified`, `synchronous=FULL`. Schema is `persistence/schema.sql` (`user_version` 2). M01's `runs`/`active_run` tables in an existing database file are left untouched and unused (tested).

3. The M01 "1,024 cells" count had been dropped from the legend; restored and asserted.

## Known limits / unverified

- No human visual QA of colors/outline readability. At tick 10, 1,012 of 1,024 cells change, so the "changed this tick" outline covers nearly the whole grid; it is accurate, not selective.
- Full cells receiving zero credit is verified by tests (seed 42 contains full cells; an all-full fixture credits 0); not separately observed in the browser.
- The `zero_inflow` fixture UI was tested with mocks and via API, not clicked in a real browser (requires `GENESIS_DEV=1`).
- No snapshots, replay or restart-from-history verification beyond reloading committed state (M03). The RNG is used only at initialization, so no RNG state is persisted yet. Hash equality is shown for seed 42 on this machine/Python only.
- Event history lists 50 newest with "Load older"; changed-cell table shows the first 200 rows (all cells are outlined on the grid).
- Polling (250 ms running / 1 s idle) sends the full frame; no deltas yet.
- Storage: ~1,000 delta rows per inflow event; archive growth is a later (M15) concern.
