# M13 validation — selective memory inheritance

Date: 2026-11-12. Status: **implemented; automated tests passed; fixture check passed in Chromium (Playwright). One live trial (2026-11-12) ran to extinction with no births, so live memory inheritance has not yet been observed.**

## Scope

| | |
|---|---|
| State | **State schema 12**, rules `m13-rules-1`.<br>• Memory records gain the kind `inherited` with an `origin`: from (parent), source_id, source_kind, source_tick, ancestor_id.<br>• `origin` is serialised only for inherited records, so earlier records hash identically.<br>• No DB layout or frame change (still v9). |
| `reproduce(…, memory_ids?)` | Up to `inherit_memory_max` (2) of the parent's own **active** record ids.<br>**Checked before any mutation, after the endowment checks:**<br>• duplicates or a non-list → `invalid_arguments`;<br>• more than 2 → `over_action_limit`;<br>• any id that is unknown, another organism's or already forgotten → `invalid_memory`.<br>A rejection has no effect at all. |
| Cost | **Transmission:** `memory_write_fee_per_kib` (1) per started KiB of the selected records' text, paid by the parent (`inheritance_fee`, dissipated).<br>**Affordability:** it is included in the check (fee + transmission + endowment + keep 10). |
| Retention | Each selected record survives independently with `inherit_memory_retention_percent` (50). The rolls come from the same per-birth PRNG, after the lifespan and tendency draws. Every roll is logged with the selected, retained and dropped ids. **A child may receive none.** |
| The copy | A survivor becomes the child's own record `<child>-m0000n`:<br>• kind `inherited`;<br>• text `"[from <parent>] <original>"`, truncated on a character boundary to the 256-byte record limit;<br>• acquired at the birth tick (age 0), placed where the parent experienced it;<br>• the source's keywords plus `inherited`, and the source's salience;<br>• an `origin` naming the first ancestor along an inheritance chain.<br>It counts toward the child's memory limits and upkeep. The parent's records are never changed; there is no aliasing. |
| What the child sees | In recall, an inherited record gives the offset from the child's own position, plus `inherited_from` and `originally` (the source kind). The memory rules text adds: *"Records marked inherited were passed on by your parent at your birth: claims about its past, possibly outdated, not your own experience."*<br>Source ids and live references are not shown, and inherited records never trigger reflection. |
| Observer | • `GET /api/organisms/{id}` adds `inheritance` for run-born organisms: the logged birth record.<br>• The organism panel's **Inheritance** section shows the parent link and event, a tendency table (parent, child, inherited ± / fresh draw), and *"Parent selected …: kept …; dropped …"*.<br>• The memory inspector marks **inherited claim** with its origin.<br>• The parent's outcome reads *"…; passed 1 of 2 memories"*. |
| Fixture (dev, scripted) | `birth_memory`: the parent gathers records for 8 ticks. Its attempts are rejected `invalid_memory` (an id it never had) and `over_action_limit` (3 ids), then it gives birth passing its two newest recalled outcomes. Retention is a labelled 75% here (the default is 50%), so seed 42 keeps one and drops the other (rolls 74 and 79). The child then accumulates its own records. |

Not added: full autobiography transfer, identity continuation ("reincarnation"), weight inheritance, and any automatic "best memory" selection by the engine (the parent chooses).

## Choices made within the proposals (reversible)

1. **Transmission cost** = the memory write rate on the selected text, paid by the parent and checked in affordability. The proposal left the exact per-copy cost open.
2. **The prefix `[from <parent>]`** is part of the stored text, so the claim is labelled wherever the text appears, including in a model prompt. Combined with the per-record limit, it can cause truncation (tested).
3. **The copy keeps the source's place.** With recall offsets, a child can find where its parent experienced something; the values may be stale.
4. **Inherited records do not count toward the reflection trigger**, to avoid an instant reflection at birth.
5. **The fixture uses 75% retention**, labelled, so the default seed demonstrates a partial outcome. Tests cover 50% across seeds: none, some and all occur.

## Live trial (2026-11-12)

**Run `72e6ce82…`.** 10 organisms on local `Qwen3.8-27B-Uncensored-MLX/8-bit`, 16 × 16, seed 42, seeded tendencies, M13 code. Ran to tick 80, then was resumed at the user's request until extinction at **tick 136**.

| | |
|---|---|
| Decisions | 387: 298 accepted, 86 rejected, 3 unparsed |
| Births / reproduce attempts | **0 / 0** |
| Messages / reflections | 8 / 28 |
| Deaths | all 10 starved (ticks 35–136) |

**Why no births.**

- The configuration matched the M12 trial (`c366ebba`), which had 2 births. The M13 prompt text differs slightly, though: the reproduce rule mentions `memory_ids`, and the memory rules mention inherited records. Sampling seeds derive from the request hash, so the runs diverged from tick 6.
- org-0003, the M12 run's first parent (at tick 20), stayed at 40–49 energy up to tick 21. In the M12 run it had 55–64, and it needs 40 plus a margin to reproduce.
- Organisms still planned for it: 14 explanations mention building reserves for reproduction, e.g. org-0003 at tick 28: *"Top up energy before considering reproduction; current cell has 72 energy."*

**Assessment.** Under the M13 criteria, controlled cases (fixture, 30-seed test) satisfy "partial and imperfect". A live parent selecting memories has not been observed. Births are rare and sensitive on the scarce 16 × 16 map: 2 in one run, 0 in this one.
