# M08 validation — costly memory and bounded recall

Date: 2026-11-10. Status: **implemented. Automated tests passed. Roadmap manual test passed in Chromium (Playwright). The live-model A/B observation (criterion G) was run on 2026-11-11: memory measurably changes local Qwen's decisions; DeepSeek-V3 ignores it (see [experiment](../../experiments/m08_memory/README.md)).**

## Scope

| | |
|---|---|
| State | **State schema 7**, rules `m08-rules-1`. Each organism has an active memory set, `World.memories`: records ordered by id, each with owner, kind, acquisition tick and age, acquisition cell, text, keywords and fixed salience. It is part of the state hash, the snapshots (format 3) and replay. Organisms gain `memories_written`, which names the next record. Schema ≤ 6 runs keep their rules and byte-identical hashes. |
| Writing (`memory.write.v1`) | After each decision of a surviving organism, the engine writes:<br>• an `observation` of the cell it stood on (energy, loose and packed material, others in view);<br>• an `outcome` record for an accepted action. Rejections and unparsed output stay diagnostics, outside memory.<br>An observation identical to the latest active one of the same cell is not written again. Text is limited to 256 UTF-8 bytes, cut on a character boundary. |
| Costs | **Write:** 1 energy per started KiB written in that tick. A write is affordable only if at least 1 energy remains; otherwise it is skipped with a `memory_skipped` diagnostic (`insufficient_energy`) and changes nothing.<br>**Keep (`memory.upkeep.v1`):** 1 energy per started KiB of active text on every 10th tick, charged right after basal upkeep and before the starvation check, like upkeep.<br>Both costs are separate ledger categories (`memory_write_fee`, `memory_upkeep`) that count as dissipation. |
| Limits and eviction | At most 64 records and 16 KiB per organism. A write that would exceed either limit first forgets the oldest acquisitions, with a stable id tie-break. The `forget` delta carries the full record, so history keeps it: the archive is complete while active memory is bounded. |
| Recall (`recall-v1`, cognition) | Each record gets three components, summed without weights:<br>• **recency:** min-max normalised ticks-ago; all equal → 1;<br>• **relevance:** Jaccard overlap between the record's keywords and the current situation (resources on its cell, others in view, last accepted action);<br>• **salience:** observation 1, outcome 2, divided by 2.<br>Ranking: score, then fewer ticks ago, then id. Up to 8 records are taken while their text fits in 2,048 bytes. Recall is free and changes nothing. |
| Boundary | The engine gives cognition only `MemoryView`s of the organism's **own** records: offset (dx, dy) from its current position, ticks ago, age then, and text. No coordinates, tick or other organism's memory are included. The organism moves only by its own accepted moves, so the offset equals what path integration would give it. |
| Request and prompt | The context gains `memory` (rules text, active count and bytes, limits) and `recalled`. Scores and query are stored on the request as observer-only `recall`, outside the input hash, because they are derived from the same inputs. Prompt **`decision-v2`** adds a short memory paragraph; contexts without memory still render `decision-v1`. New runs seal `decision-v2` in their provider profile. |
| Observer | `GET /api/organisms/{id}` (also with `at_tick`) returns `memory`: limits, active records (with cell, tick and the event that added them), forgotten records with forgotten tick and event, and the recall behind the latest decision. `GET /api/events/{seq}` includes `memory_changes`. The Dashboard has a **Memory** section in the organism panel, and the Decision inspector lists the recalled records actually given. The frame contract is unchanged (v7). The run summary states the energy spent on memory. |
| Persistence | DB layout **6**: the new table `event_memory_changes`, migrated additively from 5 and recorded in `schema_migrations`. No history is rewritten. |
| Fixtures (dev only, scripted) | `memory_return`: visit a 25-unit stockpile, walk out of view, walk back using only recalled records (labelled `recall_max` 16).<br>`memory_budget`: a 6-record / 1 KiB memory walking a square until writes become unaffordable and it starves.<br>Earlier fixtures (M04–M06) set `memory_enabled = false`, so their behaviour and the recorded-response files are unchanged (`record --check` passes). |

Not added: reflection (M11), messages or inheritance of memories (M09/M13), semantic embeddings, organism-chosen notes or forgetting, and any claim of learning or adaptation.

## Choices made within the proposals (reversible; see DECISIONS.md)

1. **What is written.** Writes are fully automatic and deterministic, one or two records per decision. The organism cannot yet choose what to remember or forget. An organism-authored note (a paid field in the proposal) is an obvious later option, but it would change the action schema.
2. **Location as an offset.** Records keep their acquisition cell engine-side; cognition sees only the offset from where it is now. Stored text holds no relative directions, so it never goes stale geometrically, only in its values.
3. **Write affordability.** "Unaffordable" means the fee would leave less than 1 energy, so memory never kills by itself. Upkeep, like basal upkeep, can starve.
4. **Dead organisms' memory** stays in state, frozen: it is no longer charged or recalled. Retiring it at death would be an equally valid rule and would matter for M13.
5. **Salience** observation 1 / outcome 2 is an author choice. In the smoke run it measurably pushes old observations out of an 8-record recall, behind recent outcomes: at tick 7 of `memory_return` with the default `recall_max` 8, the stockpile record was no longer recalled and the scripted walker stopped one cell short. That is a property of the default, not a defect. The fixture uses a labelled `recall_max` of 16 to demonstrate the path itself.
6. Memory code lives in `engine/memory.py` (world rules: writes, eviction, upkeep, the view boundary) and `cognition/retrieval.py` (recall). ARCHITECTURE listed `cognition/memory.py`, but costs and active membership are state mutations, and only the engine may commit those.

## Roadmap manual test (Chromium via Playwright, all checks passed)

The backend ran on port 8011 with `GENESIS_DEV=1` and a scratch database; the production bundle was served by `vite preview` on port 5181. Your own servers on 8000/5173 and `data/genesis.sqlite3` were not touched.

1. **Visit-and-return fixture.** The tick-5 decision was taken at (13, 10), three cells east of the stockpile. It recalled 7 of 7 active records, including `org-0001-m00001: observation, 4 ticks ago at offset (-3, 0) — "cell: energy 34, loose material 25, packed material 0"`. The outcome was *Moved west*, and the panel then showed position (12, 10).
2. **Observation vs remembered tick.** The supplied observation (radius 2) does not contain the stockpile cell. The record still shows the values from tick 1.
3. **No remote refresh.** The remembered text stayed as stored; unit test `test_remembered_values_are_never_refreshed_from_the_world` covers this.
4. **Recalled IDs in the next input.** Tick 9: position (10, 10), carrying 5 / 20. The recall-score table listed 12 candidates with their components and query keywords (`energy, extract, material`).
5. **Fill the budget, then restart.** In `memory_budget` the organism starved at tick 14; the panel read `6 / 6 records, 250 / 1024 bytes active; 24 written in its life`, with *Forgotten records (18)*. After killing and restarting the backend, the panel read the same values, restored from `snapshot @ tick 14 + 0 replayed ticks`.

No page errors were recorded. Screenshots are in the session scratchpad and are not committed.

## Known limits and open items

- **Live A/B observation (criterion G), done 2026-11-11.** Experiment `m08-memory-ab-v1` used hand-built worlds and conditions that differ only in the recalled record ([details and raw data](../../experiments/m08_memory/README.md)).
  - **Local Qwen3.8-27B:** moved toward a remembered rich cell it could not see in 20/20 probes (west) and 20/20 (east), versus 0/20 with no memory and 0/20 toward a remembered barren cell (Fisher p ≈ 1.5e-11). In closed-loop episodes it reached the resource 5/5 with memory and 0/5 without; the recalled offset updated correctly as it walked.
  - **DeepSeek-V3 (Replicate):** answered `wait` in all 160 decisions regardless of memory. Delivery of the memory was verified, so this is the model's behaviour.
  - Influence therefore depends on the model; none of this is evidence of learning.
- **Behavioural cost.** An organism deciding every 4 ticks now pays about 1 extra energy per decision, plus about 1 energy every 10 ticks per KiB of memory it keeps. Whether that is viable is an ecological question (O01, O03); nothing has been tuned for survival.
- **Database migration.** Your running backend (old code) still uses DB layout 5. The new code migrates `data/genesis.sqlite3` to layout 6 on its next start: additive, history untouched. Old schema-6 runs keep running without memory. A schema-6 recorded-fixture run already in progress still matches its recordings, because those recordings did not change.
